==> primary key--


A Primary Key is a column (or combination of columns) that uniquely identifies each row in a table.

Main properties of Primary Key
Unique → Duplicate values are not allowed.
NOT NULL → A primary key cannot contain NULL.
One primary key → A table can have only one primary key constraint, although it can contain multiple columns (composite primary key).

#@ difference between truncate vs delete


delete -> dml command 
       -> use where 
       -> delete can delete selected row also
       -> we can use condition
       ->it can use order by ,limit et
       -> it follow row by row deletion symentic
   
       -> it can be rolled back when used within a transection under appropriate  transactional condition.
       -> delete does not reset auto_increment


truncate ->
-> ddl command
->not use where
-> truncate it remove all rows
-> no condition
->can not use anything
-> it deallocates table data more directly
-> truncate uses implicit commit so no roll back
-> truncate reset auto_increment it mean when next time we insert data starts from one(1).


---------------------
--------------------
@# diff delete vs drop

delete -
-> dml command
-> delete removes rows
-> after delete table structure remain
-> in delete column,constraint,index will remain
-> where allowed
-> in delete selected or all row will deleted 
-> roll back
-> delete does not reset auto_increment

drop-
-> ddl command
-> it remove database object itself
-> after drop table structure remove
-> but in drop all 3 will remove
-> where not allowed
-> but in drop it is not possible
-> auto commit
-> object is remove permanently so no concept of auto_increment

### TCL commands-
- tcl command are used to manage transaction in a database
- a transaction is a group of sql statement that should be treated as one logical unit of work

common commands-
- commit
- roll back
- savepoint
-rollback to savepoint
- release savepoint
- start transaction


synatax (transaction)-
       start transaction ;
       sql statement1;
       sql statement2;
       sql statement3;
       commit;
or 
begin;
sql statements
commit;

@# save point-
* savepoint is a temporary checkpoint created inside a transaction
* it allow us to partially undo a transaction without undoing the entire transaction


syntax-

start transaction
operation1;
operation2;
savepoint sp1;
operation3
opeartion4
rollback to sp1;


-> the above syntax will undo the operation3 and operation4
-> it will keep operation1 and operation2 and it will keep the transaction active,which allow us to execute more sql statement 
-> we can finally commit and rollback

note-
Rollback to savepoint does not end the transaction

##  Column level vs Table level constraint
columnlevel -

example-

table level -
in the table level constraint the condition is defined separately it is usefull when the condition involves multiple column

example-
create table employee28(id int,name varchar(20),experience int,salary decimal(10,2) ,check ((experience<=2 and salary>=15000) or (experience>=2 and salary>=25000)));

@@ Advantages of foreign key-

1. maintain referential integrity-
--> a foreign ensure that a value in the child table must correspond existing in parent table  


2. prevent  invalid data -
--> it stops user from inserting unrelated or invalid ids into  the child table 


3. maintain relationship between two table-

4. prevent orphan record 
--> an orphan record is child record whose parent no longer exist

5. it control delete operation-

6. it control update operation

7. makes database design more reliable 



Syntax--
       create table parenttable(id int primary key) 

       create table childtable (id int primary key ,parentid ,foreign key(parentid) reference parenttable(id) ;

@#@ PDBC - (PYTHON DATABASE CONNECTIVITY)-->
Python database connectivity is mechanism that enable python application to communicate with relational databases using standarise api 
--> python follow a standard called PYTHON DB-API2.0 .
--> This ensure that different database module behave similarly
--> Before DB-API every database had its own way of connecting and executing query 
--> DB-API provides a common standard code become portable , consistent , easy to maintain
--> It is not a library it is a set of rule 


ADVANTAGES OF DB-API :-

1. database independence 
2. easy to switch
3. standard coding type 
4. secure (it support parameterize query )
5. reduce development time

PYTHON DATABASE MODULE- (drivers)

1. To connect python with database we use specific libraries
 for example-
           
MySQL        mysql-connector-python,pymysql
PostgreSQL psycopg2
SQLite sqlite3 (built-in)
oracle cx_Oracle
MongoDB pymongo
 

2. A database driver or module is a python library that allow your program to connect to a database , execute sql queries and fetch result 

3. This modules follow PEP249 that why their structure is similer

4. PEP249-- python enhancement proposal

5. this proposal tells how python database module should behave and what method they must provide 


@## DATABASE CONNECTIVITY ARCHITECTURE-

user/application program --> DB-API 2.0 Interface(PEP249) ---> database driver (mysql-connector) --> database server(MySQL/PostgreSQL)--> data storage

work flow--

User / Application Program
          ↓
    DB-API 2.0 Interface
        (PEP 249)
          ↓
     Database Driver
   (mysql-connector)
          ↓
     Database Server
   (MySQL / PostgreSQL)
          ↓
      Data Storage
